# 全路寬道具補給排（2026-10-09）

使用者要求增加賽道道具數量，四名玩家也要有橫跨馬路的完整補給排。此輪調整既有十一圖的道具配置及刷新，不改賽道拓撲、地形、捷徑或車輛操控。

## 設計依據與原創配置

參考 [Nintendo《Mario Kart 8》官方手冊](https://www.nintendo.com/eu/media/downloads/games_8/emanuals/wii_u_6/mario_kart_8/ElectronicManual_WiiU_MarioKart8_EN.pdf) 的經過道具箱取得道具流程，以及 [《Mario Kart World》官方更新紀錄](https://en-americas-support.nintendo.com/app/answers/detail/a_id/68580/~/how-to-update-mario-kart-world) 2025-09-23、Ver. 1.3.0 縮短道具箱復活時間的調整方向。以下數量、距離與時間是本專案的原創調校，並非參考遊戲的精確配置。沿用原創道具及視覺，不加入 Nintendo 素材。

原先每圈三個半路寬選線區、十二箱，正常車道可能錯過。新版每圈四至七排（2026-11-17 自六至十排下修，讓每排補給成為選擇而非持續補滿），每排六至七箱；依實際路寬對稱排列，正常路線及兩側車道都能經過。目標密度依約 175 m 的路程估算，再移至安全候選段。最初一排距起點至少 40 m，末排距終點至少 25 m，任兩排弧長間距至少 45 m。曲率與跳台避讓使實際間距不完全相等。

箱中心與路邊保留 0.65 m，橫向相鄰中心最多 1.25 m。排寬同時查詢前後 2 m 的道路，防止在收窄處伸出路外；箱高度依自己的實際路面取樣，避免傾斜路面漂浮或埋入。每箱獨立冷卻 **2.5 秒**，取代 5 秒，讓後方玩家及下一批車更容易補給。

## 安全與規則邊界

- 排列避開每座跳台前 8 m 至後 68 m 的起降段，保持中央地面繞行線與空中選線的辨識。
- 避開主題移動障礙所在弧長前後 16 m；以前後 8 m 切線夾角篩除尖銳彎心，使補給盡量位於可看見、可選線的路段。
- 背包維持兩格、滿格不消耗箱子、每步最多拾取一箱、五種道具等機率及 0.65 秒使用冷卻。未新增雙倍箱、名次權重、道具種類或攻擊傷害。
- CPU 與真人讀同一份配置、使用同一伺服器權威拾取／冷卻；練習模式仍沿用既有無對手駕駛規則。

## 實作

`src/game/core/items/itemRows.ts` 集中配置及安全排點；`trackData.ts` 在最終道路寬度生成後配置完整補給排。舊半幅箱座標改名為 `ITEM_ROAD_CLEARANCES`，僅保留其既有道路收窄避讓用途，避免新增補給反過來改變整圈路寬。加速帶保持既有位置及數量。

`ItemBoxRows.tsx` 以兩組共享 `InstancedMesh` 繪製箱體與框線，沿用旋轉、浮動及冷卻縮小提示。基本渲染只需兩次 draw call，陰影 pass 另計。每幀重用矩陣與變換物件，增加箱子不增加逐箱 React 元件及獨立繪圖呼叫。

客戶端與伺服器均由相同賽道資料生成位置，快照沿用每箱 ID／冷卻時間。協定升至 **20**，防止舊客戶端用舊位置解讀新箱 ID；前後端須同步更新，已開啟的電腦及手機頁面須重新整理。

## 驗證

`npm run check -- -- --maxWorkers=2` 通過 59 檔、501 項測試（含 lint／strict TypeScript）；`npm run build` 通過。新增十一圖路寬／補給覆蓋／實際高度／間距，以及四車掃掠拾取不同箱、2.5 秒復活共 22 項純規則測試。既有十一圖 CPU 三圈、跳台與落地避讓及道具權威測試均通過。

正式版 Brave 的鍵盤花谷、手機尺寸台北兩項瀏覽器測試通過：真人沿固定側線行駛、不逐箱追蹤，在三個不同補給排取得並使用道具；四車均取得補給，已取箱子重新出現，畫面及執行沒有錯誤。已檢視接近完整補給排的兩張截圖。中央跟車會競爭同一列箱子，不能把每車每排保證拾取當作驗收前提；四車同時穿過不同橫向箱子的公平覆蓋由純規則測試驗證。

本機局部省電畫質樣本：鍵盤約 60 FPS／p95 17.9 ms、227 calls，手機尺寸約 60 FPS／p95 17.4 ms、112 calls；整體 call 數包含景物及所有車，並非只有道具排。這些數字不是手機真機或完整賽事效能驗收。尚未部署；增加補給後的真人攻防節奏仍需實玩評估。
