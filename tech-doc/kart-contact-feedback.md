# 互撞修正與追逐玩法提案

2026-10-08。使用者回報互撞黏住、遊玩主要是開車與拿道具。本輪修正既有「互相推開、短暫減速、車身偏移」契約。下方尾流提案已由使用者以「好」核准，2026-10-09 實作規則與驗證見 [尾流追逐實作](slipstream-implementation.md)。

## 已修正行為

- 權威 Rapier 每步檢查持續接觸的車對車碰撞面，逐對處理，不只依賴首次接觸事件。
- 以法向相對接近速度判定撞擊；正撞兩車反彈，追撞轉移前向動量，側擦保留主要前進速度。沿兩車中心方向校正法向符號。
- 保留解算後的共同法向速度，再給兩車相反的分離速度。不直接修改位置或補回撞擊前速度。
- 接近速度至少 0.7 m/s 才算撞擊。目標相對分離速度為 `clamp(接近速度 × 0.45, 4.4, 8)` m/s；持續貼住時為 1.2 m/s。已分離的低速接觸不追加反應。
- 只衰減撞擊的切向速度：一般保留 94%，接近速度至少 8 m/s 時保留 88%。同速側擦不因絕對高速被視為重撞。
- 每步讀回實際橫向速度；反應後 0.3 秒短時較低抓地力，避免下一步立刻消掉側向推力。
- 回饋沿用 revision、車身壓縮／閃光和已有聲音，每車冷卻 0.35 秒；冷卻不阻止物理分離。普通互撞不加入失控鎖定或道具無敵。

## 輪胎範圍與接觸遮罩

Kestrel 車輪中心半距 0.72、輪圈／胎面半寬約 0.158，縮放後可見外半寬約 0.632 m；舊權威碰撞外半寬約 0.504 m，會讓輪胎先穿進另一車。

新增僅車對車接觸的圓角形狀：基礎半寬 `0.76 × 0.72`，圓角 `0.12 × 0.72`，外半寬約 0.634 m。密度為零，質量仍由原道路形狀決定。

道路車體只接觸道路／護欄／主題障礙；車對車形狀只接觸其他車對車形狀。道路車體保留 0.58 基礎半寬與原坡道間隙，單人練習原形狀保留。直接擴大全部碰撞範圍曾使窄彎回歸失敗，分組後重新驗證。

重賽恢復兩個形狀，完賽／DNF 將兩個形狀改為 sensor，刪除玩家時隨剛體釋放。不新增輸入或快照欄位，協定維持 18。

## 驗證

新增純碰撞測試涵蓋正撞、追撞、高速側擦、接觸順序翻轉、垂直／已分離接觸。真實 Rapier 驗證正撞、追撞、側擦後持续輸入，以及四車擠壓後恢復行駛。保留十一圖三圈、坡道、跳台、道具、牆撞、重賽與 DNF 驗證。

最終 `npm run check` 通過 56 檔／453 項，正式建置與 `git diff --check` 通過。Brave production 四種情境通過：兩個真實鍵盤玩家互撞後距離增加且仍可轉向、漂移充能／檢查視角、護欄反彈，以及定速直線跨接縫。已檢視兩個玩家畫面，沒有頁面錯誤。

直線回歸原本在 GO 自動推進後才起算，剩餘路段不足，會因取樣數失敗；測試改用實際煞車／倒車回到起跑直線再加速，保留 16.6–17.4 m/s 的實際位移限制，未覆寫車輛位置或放寬速度判定。完整檢查後的 E2E 流程修正另通過 lint／TypeScript 檢查。

這些是本機自動化驗證；互撞強度、尾流提案與主觀遊玩感仍需真人實玩，未新增手機真機／跨網路四人長時間驗收，也未部署。

## 已核准設計：追車 → 蓄尾流 → 拉出超車

目前漂移與選線都有獎勵，但靠近前車缺少持續的駕駛收益。建議下一輪增加追逐循環：

1. 收進前車尾流帶，穩定跟車約 0.8 秒，逐步加強流線及聲音回饋。
2. 蓄滿後拉到側邊超車，取得約 0.7 秒一階加速，仍需操控出彎與避開其他車。
3. 前車改變行車線會讓追車者重新對準；碰撞打斷蓄力，過度貼近也有被陷阱命中的風險。

候選限制：同路面高度、同向、前方約 3–10 m、橫向約 1.2 m 內、雙方至少 8 m/s；只鎖一個前車，不隔樓層、隔護欄或隔彎蓄力。由伺服器判定，CPU 與真人一致；追車／拉出成功才有獎勵，不按額外按鍵。

設計目標是讓「追上 → 找出口 → 超越 → 守住」形成反覆的決策。上述為核准的設計起點，正式規則、彎道與變線判定、回饋、CPU、協定 19 與驗證界線見 [尾流追逐實作](slipstream-implementation.md)，數值仍需實玩平衡。
