# 台灣四圖重製提案｜2026-10-08

> 後續核准：本文件記錄環境美術那一輪。使用者其後核准台北道路與共享操控的 [駕駛手感試作](driving-feel-implementation.md)，台北拓撲與特技規則以該文件及 `document.md` 的最新紀錄為準。
**狀態：使用者於 2026-10-08 以「可以 很漂亮」核准設計與台北概念方向；四圖環境重製已接入遊戲，建置與瀏覽器回歸驗證通過。** 範圍為台北、九份、高雄、阿里山。原創拓撲、三圈、CP 與權威／練習玩法沿用既有核准版本；此輪重建場景、資產及材質，逐圖回歸可玩性。

沿用「寫實街機」：建築、材質與光影有真實結構，路線則為原創、壓縮和誇張的賽車環境。地理只提供辨識元素；地標距離、相鄰關係及道路配置均為虛構。各圖八段、三圈；主路可繞開大跳，捷徑與獎勵支路均在合法 CP 區間內合流。

實際交付及與提案的差異見 [四圖環境實作](taiwan-environment-implementation.md)。

## 重製要解決的畫面問題

1. 城市改為連續街廓：深騎樓、店面凹槽、簷口、山牆、屋頂和後排樓房。近景先做好六至八種可重組建築模組，避免整圈都用同一盒子加窗。
2. 地形承托道路：山壁、台地、擋土牆、碼頭、橋柱和梁體形成完整結構；所有主路、支路與地基要一起檢查高低差。
3. 每一段有前景／中景／遠景：路緣與障礙清楚，城市密度或林冠做中景，主要地標與山脊做遠景。細節密度集中在駕駛看得到的位置。
4. 材質用真實尺度的磚縫、石材、木紋、金屬接縫和濕度差異；優先可共享的材質／紋理及實例化，避免靠大量單獨小方塊表現細節。
5. 暮色、暖燈、薄霧與陰影分層；路面亮度要高於可撞的路緣陰影。霧不遮住下一個彎、障礙預告與跳台落點。
6. 先做台北代表段的實際 Blender／GLB 和遊戲光照驗收，再按同一品質標準擴展；生成概念圖是方向參考，不當作可執行模型或效能承諾。

## 台北

**Track Name｜台北・霓虹疊城**

**Theme｜** 老城騎樓、夜市與捷運高架壓縮成三層都市迴圈。

**Visual Identity｜** 六個辨識元素：朱紅城門／燕尾屋脊、連棟紅磚街屋與騎樓、節式青綠玻璃高塔、銀青捷運列車、密集棚頂夜市、河岸混凝土堤牆。主要畫面是深藍暮色和暖黃店燈，雨後反光只落在可辨識的濕線。參考 [北門](https://travel.taipei/zh-tw/media/audio-guide/details/218)、[迪化街街屋](https://www.travel.taipei/zh-tw/pictorial/article/18490)、[101 建築概念](https://www.taipei-101.com.tw/ja/concept/null)。

**Landmarks｜** 北門意象城樓縮成收口彎；迪化街意象騎樓柱列形成技術走廊；101 意象節式高塔的低層裙樓承托爬坡與大半徑漂移彎。三者均以原創建築模組呈現，不照搬真實平面。

**Track Layout｜** 街面 → 騎樓 → 捷運平台 → 高塔裙樓 → 屋頂層 → 夜市 → 河岸 → 城門。總高差目標約 30 m，爬坡前有回正段，下坡後有寬回復段。

**Gameplay Sections｜**

| 段 | 操作與場景作用 |
| --- | --- |
| 1 城門廣場 | 寬起跑／超車段；拱洞前先緩彎預告收口，門洞出口能看見下一段。 |
| 2 連棟騎樓 | 柱列形成左右折角技術彎，店面凹槽顯示護欄外空間；柱子是明確可撞邊界。 |
| 3 捷運換線 | 跨入高架層前選擇寬安全線或較短的列車交會支路。列車進入前有燈與聲音預告。 |
| 4 高塔裙樓 | 連續爬升接長漂移彎；塔基就是彎道內壁，出口恢復寬度。 |
| 5 空中大道 | 高速超車段，以橋梁結構、遠方高塔與曲線路緣預告方向。 |
| 6 棚頂大跳 | 地面主路延續，側線從屋頂坡道跨過街谷，落到寬屋頂平台後才下坡。 |
| 7 夜市蛇行 | 攤棚和貨架圍出連續短彎；濕磚內線抓地較低，乾燥外線較穩。 |
| 8 河岸回程 | 從屋頂下降到開闊河岸，回復、使用道具與最後超車，再回到城門。 |

**Gameplay Gimmick｜** 高架與街面交叉、列車交會支路、夜市濕乾線；主要環境轉換是密閉老街 → 開闊屋頂天際線，再落回暖光夜市。

**Moving Obstacles｜** 原創捷運列車穿越獎勵支路；主要地面線持續通行。列車不放在急彎頂點或落點。

**Shortcut｜** 第二段騎樓內街：少走一個外街大彎，代價是更窄的柱列與兩次快速反向轉向；失誤撞柱會損失速度。合流後設共同 CP，不跨越檢查點。

**Risk/Reward Route｜** 第七段夜市濕磚內線：更小轉彎半徑與加速條，提高出彎速度；需更早轉向，失誤滑向護欄。與第二段捷徑不同。

**Spectacle Moment｜** 從棚頂飛躍街谷，捷運在下方穿越，遠景高塔與整片夜市燈光同時展開；攝影機仍以落點和車身可見為優先。

## 九份

**Track Name｜九份・金霧飛城**

**Theme｜** 立體茶樓山城與礦業台地連到海岸。

**Visual Identity｜** 六個辨識元素：紅燈籠、沿坡石階與石牆、木窗茶樓與深色瓦簷、十三層式階地廠房、鏽色礦車／礦坑、黃褐與蔚藍分層海面。建物踩在岩層和擋土台地上，密度由巷道向海岸漸開。參考 [九份燈籠／茶樓／石階](https://newtaipei.travel/zh-tw/tour/32)、[十三層與山海](https://newtaipei.travel/zh-tw/tour/400)、[陰陽海](https://newtaipei.travel/zh-tw/Attractions/Detail/109992)。

**Landmarks｜** 山坡茶樓群形成窄巷與回轉平台；十三層意象選煉廠成為可駕駛的階地彎道；陰陽海是低海岸路段的開闊方向參照。

**Track Layout｜** 燈籠街 → 茶樓髮夾 → 廠房階地 → 礦坑 → 山脊 → 跨谷跳台 → 海堤 → 屋下上坡。總高差目標約 42 m；真實石階改為可駕駛連續坡面，旁側石階保留辨識。

**Gameplay Sections｜**

| 段 | 操作與場景作用 |
| --- | --- |
| 1 燈籠迎客街 | 寬入口，暖燈串沿路線預告上坡與首彎。 |
| 2 茶樓髮夾 | 石牆、茶樓露台包住兩個不同半徑髮夾，出彎可回正。 |
| 3 選煉廠階地 | 大幅爬升的長彎，以混凝土台地和屋簷交錯建立高度感。 |
| 4 礦坑回復 | 稍寬的低光直段整理車速；出口光點與護欄預告方向。 |
| 5 山脊高速 | 稀疏建物露出海景，長緩彎提供高速超車。 |
| 6 山城跨谷 | 側線從礦運平台離地，跨谷落到寬露台；保留山壁地面繞行路。 |
| 7 陰陽海海堤 | 長下坡後的平緩回復段；浪花預告內側路面轉濕。 |
| 8 屋下回程 | 穿過茶樓下方石拱，連續上坡回到起點，保留超車寬度。 |

**Gameplay Gimmick｜** 廠房台地與山壁決定升降和彎序，海岸濕線降低抓地；主要環境轉換是暖光密集山城／暗礦坑 → 開闊冷色礦海。

**Moving Obstacles｜** 礦車在廠區獎勵側線往返，軌道、警示燈及進出洞口預告其行程，中央安全線能繞過。

**Shortcut｜** 第三至四段維修礦坑：切掉一個外側台地長彎；入口窄、內部有兩個折角，需準確入線。撞壁或合流角度失誤會失去省時收益。

**Risk/Reward Route｜** 海堤低線較短並有加速條，但預告浪花後會降低抓地；高線較寬、較乾燥。海水本身顏色作辨識，濕滑由浪花帶來，不把陰陽海的天然色差當作油污。

**Spectacle Moment｜** 跨谷離地時視野越過茶樓屋頂，階地廠房和黃藍海面一次展開；落點先可見，出落點後再接彎。

## 高雄

**Track Name｜高雄・轉港狂潮**

**Theme｜** 以倉庫、吊運系統、轉橋與海灣建築組成港灣競速環境。

**Visual Identity｜** 六個辨識元素：紅磚倉庫與鋼屋架、彩色波紋貨櫃、港灣吊臂與鋼索、白色流線轉橋、海浪／珊瑚意象建築、港池與低水岸。暖夕陽照亮路面，海水和金屬採較冷反光。參考 [駁二倉庫與鐵道](https://khh.travel/zh-tw/attractions/detail/6/)、[大港橋](https://khh.travel/ja/attractions/detail/1190/)、[高流建築](https://khh.travel/zh-tw/attractions/detail/1175/)。

**Landmarks｜** 駁二意象倉庫供賽道穿行；大港橋意象側橋直接改變通行時機；高流意象弧形基座塑造高速漂移彎和沿岸視野。

**Track Layout｜** 倉庫 → 裝卸場 → 港橋 → 海洋建築基座 → 吊臂跳台 → 潮汐棧道 → 水岸。總高差目標約 28 m，港橋下層有完整碼頭和通航水域。

**Gameplay Sections｜**

| 段 | 操作與場景作用 |
| --- | --- |
| 1 倉庫起跑 | 寬大道建立速度；連續山牆和大庫門預告穿庫入口。 |
| 2 穿庫技術區 | 鋼柱與貨架圍出長彎接短反向彎，出口有明亮回復區。 |
| 3 貨櫃換線場 | 吊掛貨櫃改變獎勵側線通行，提前讀警示燈選線。 |
| 4 跨港高橋 | 平順爬升；主路保留，外側白色轉橋提供帶時機成本的加速路。 |
| 5 海洋基座高速彎 | 建築裙樓／曲面平台就是漂移段承托體，出口可超車。 |
| 6 吊臂跨港跳 | 側坡離地越過低層港池，落在寬碼頭平台，地面主路仍通行。 |
| 7 潮汐低棧道 | 長下坡進入接近水面的窄緩彎，浪花預告濕線。 |
| 8 水岸衝線 | 路面重新展寬，最後道具與超車；倉庫群引回終點。 |

**Gameplay Gimmick｜** 倉庫穿行、吊運通行窗口、轉橋時機與低棧道濕滑；主要環境轉換是封閉倉庫 → 高架開闊港灣 → 低水岸。

**Moving Obstacles｜** 吊掛貨櫃升降佔用側線；白色轉橋採既有「無車才關閉／轉動、復位後開門」規則。移動船隻位於非駕駛港池，作為跳躍 spectacle 的動態景物。

**Shortcut｜** 第二段裝卸通道：庫門內窄線穿過兩間相鄰倉庫，比外側彎路短；需連續準確轉向，擦到堆料會減速。

**Risk/Reward Route｜** 第四段轉橋：開放時可取得連續加速條；入口能看見門狀態，關閉時提早留主路。橋上有車時不抽走路面，不能設計成無預告陷阱。

**Spectacle Moment｜** 吊臂旁的大跳越過緩行貨輪，白色橋與海洋建築在兩側，落到夕陽反光碼頭；落地區不設吊掛障礙。

## 阿里山

**Track Name｜阿里山・雲海追光**

**Theme｜** 木站、茶園、巨木與森林鐵路構成日出山道。

**Visual Identity｜** 六個辨識元素：木造站屋、紅色森林列車、粗大檜木／根系、茶園等高梯田、岩壁木棧道、日出雲海。森林近景樹皮與苔蘚清楚，中景林冠不規則，遠景是多層山脊。參考 [阿里山經典景觀與茶園](https://www.ali-nsa.net/?lang=1)、[森林鐵路與巨木](https://recreation.forest.gov.tw/Forestry/FR?typ=11&typ_id=0900041)。

**Landmarks｜** 木站月台組織起跑與回程；巨木根系變成可通行窄彎的側壁和門洞；祝山觀日意象稜線形成高速區及大跳入口。

**Track Layout｜** 木站 → 茶園髮夾 → 根系長彎 → 鐵路交會 → 霧林爬坡 → 觀日稜線 → 雲海跨谷 → 林間下坡。總高差目標約 44 m，保留原有爬升／短回落／再爬升節奏。

**Gameplay Sections｜**

| 段 | 操作與場景作用 |
| --- | --- |
| 1 木站平台 | 寬起跑／超車，站柱、屋簷與路緣清楚分開駕駛空間。 |
| 2 茶園髮夾 | 茶列跟隨山坡等高線，兩層擋土台地組成技術彎。 |
| 3 巨木根系彎 | 根系限制內線半徑；主路繞巨木長漂移，另有窄洞捷徑。 |
| 4 森林鐵路交會 | 列車燈、鐘聲與軌道預告側線阻擋，主路可持續通行。 |
| 5 霧林爬坡 | 螺旋爬升，林冠漸疏；薄霧保留下一彎及路緣可見。 |
| 6 觀日高速稜線 | 長緩彎高速段；風口樹枝與飄帶預告側風。 |
| 7 雲海跨谷 | 側線離地越過雲谷，明確寬落點接緩彎；主路走山側橋。 |
| 8 林間下坡 | 長下降釋放速度，回站前先有平緩回復／衝線段。 |

**Gameplay Gimmick｜** 根系收口、鐵路交會和風口轉向偏移；主要環境轉換是深色霧林 → 日出稜線與開闊雲海，回程再進森林。

**Moving Obstacles｜** 原創紅色森林列車沿側線交會軌道駛過，以軌道與燈號預告；風動枝葉和飄帶顯示環境風向，避免不可見的操控變化。

**Shortcut｜** 第三段根系窄洞：切掉巨木外圈長彎，代價是窄入口和出口反向轉向；碰根會失去速度，合流後才設共同 CP。

**Risk/Reward Route｜** 第六段風口外線有加速條但橫風較強；山側內線更穩。車速和方向控制足夠時外線回報較高，不能只靠選線固定更快。

**Spectacle Moment｜** 穿出巨木林後沿日出稜線離地，紅色列車在下方木橋穿過，雲海和多層山脊展開，車身及落點維持可見。

## 設計確認後的具體交付與驗收

先製作台北城門／騎樓／高架代表段，提供真實 Blender 視圖和遊戲跟車畫面比對。同一套模組與材質要在遊戲光照下可讀，才擴展全圖及其餘三圖。

近景建築、岩壁、樹木與地標各自保留可編輯來源；碰撞隨可駕駛形狀更新，不能把細節 mesh 全部變成 collider。若新增 moving obstacle 行為，權威與練習共用規則和時間來源。CP、重生、支路進度和 CPU 必須隨新路面驗證。

省電四車場景沿用 200,000 triangles／250 calls 目標，標準畫質的陰影與反射另外量測。目標是以模組、LOD、材質重用和實例化改善品質，不在審查前承諾概念圖的細節密度和幀率。正式驗證須包含 `npm run check`、`npm run build`、雙畫質／四車／手機尺寸 WebGL、主路與捷徑合法完圈、跳台包絡、障礙預告、重生及實際截圖審查。
