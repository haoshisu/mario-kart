本輪讀取現有程式並以 Node／tsx 呼叫純核心量測，沒有宣稱完成新的真人遊玩或瀏覽器手感驗收。

《Mario Kart 8 Deluxe》的漂移出彎增益、跳躍時機增益、賽道加速物件與道具攻防，見 [Nintendo 官方刊載的操作說明](https://www.nintendo.com/jp/ichikara/aabpa/index_en.html)。本提案的設計推論是：讓玩家反覆讀路、選線、做操作，再立刻感受到回報；這不是官方對「好玩」原因的結論，也不需要照搬它的資產或全部機制。

## 第一輪範圍與優先順序

1. **操控先成立。** 保留原創車與現有速度級距，修正 Turbo 收尾的瞬間截速；漂移有明確左右方向、可控制的內外弧線和穩定回正，充能取決於有效漂移而非直行按住。鍵盤／觸控與權威／練習共用核心；小跳是否加入實體高度需另驗坡道，不能只抬 Collider 造成減速。
2. **回饋對應操作。** 原創引擎、輪胎滑動、分級充能和放開 Turbo 的聲音層，搭配已有火花／FOV／車體傾斜；聲音須經使用者手勢啟用，停車、切頁與卸載可清理。鏡頭先維持上坡和落點可讀性，避免用晃動遮掩手感。
3. **先改台北的可駕駛節奏。** 第一版只做一圖，其他三圖等待手感驗收。技術段目標每 2–5 秒有明確操作或選線；高速／回復段允許 5–8 秒留白。這是試作目標，不是 Mario Kart 的量測值。
4. **分開驗收純駕駛與對戰。** 無對手時過彎本身要有趣；再用現有 1＋3 CPU 檢查超車、道具、碰撞與重賽。CPU 學會共享漂移需在真人操控成立後處理，不新增人數、難度、吸尾流、橡皮筋或新道具系統。

比賽中收起建房／選圖面板，保留必要圈數、排名、道具和漂移提示，讓道路佔主要視野。這個呈現調整與新拓撲分開驗證。

## Track Name

台北・霓虹疊城：駕駛節奏試作。

## Theme

在老城、捷運與屋頂之間連接「漂移 → 出彎增益 → 選線 → 跳躍 → 再漂移」；周遭已完成的美術沿用，主要重排可駕駛道路。

## Visual Identity

沿用六個辨識元素：紅磚城樓、連棟騎樓街屋、節式玻璃高塔、銀青捷運、棚頂夜市、河岸堤牆。位置與距離皆虛構。城市研究沿用 [已核准四圖提案](taiwan-map-redesign.md)；本輪再讀 [101 官方設計概念](https://www.taipei-101.com.tw/ja/concept/null)，確認節式量體特色。臺北旅遊網既有北門／迪化街連結本次回讀為 403，未取得新增細節，沒有將失敗當作研究成功。

## Landmarks

三個地標實際形成道路：城門洞收束起跑線；騎樓柱列界定連續折角；高塔裙樓承托大半徑爬升漂移彎。地標輪廓維持辨識，不複製真實道路。

## Track Layout

城門起跑 → 騎樓連彎 → 捷運選線 → 高塔爬升 → 屋頂高速 → 街谷大跳 → 夜市蛇行 → 河岸衝線。約 30 m 總高差，保留三圈和共同 CP 規則。先以灰盒量測彎序和事件間隔，再決定長度與精確尺寸；不先承諾圈速或捷徑收益。

## Gameplay Sections

| 段落 | 玩家操作與回報 |
| --- | --- |
| 1 城門起跑 | 寬超車區接有預告的收口，出口立即看見第一個彎；不是長時間全油門空跑。 |
| 2 騎樓連彎 | 中長左彎充能、短回正釋放增益、反向右彎重新進入漂移；外線容易完成，內線節省距離。 |
| 3 捷運選線 | 主路保持暢通；較短內線受列車穿越影響，先讀燈號再決定冒險，合流後留回復距離。 |
| 4 塔基爬升 | 約 150–180° 長弧讓玩家調整漂移半徑，坡頂揭露方向；出彎增益接屋頂直線，不接盲急彎。 |
| 5 屋頂高速 | 開闊高速超車；加速帶放在需要提早佈線的弧線側，避免沿中央無腦自動連吃。 |
| 6 街谷大跳 | 安全地面線持續通行；側線跳台提供可讀起跳與寬落點。特技時機成功才有額外增益，失敗仍能正常落地。 |
| 7 夜市蛇行 | 三個有節奏的左右短彎；濕內線較短、乾外線較穩；進入前能分辨材質，障礙不遮急彎出口。 |
| 8 河岸衝線 | 下坡釋放速度，接最後一個可漂移彎與寬衝線直道，留下道具使用及超車空間。 |

## Gameplay Gimmick

同一個弧線提供內／外漂移半徑，而非只有避牆；出彎增益能接下一段加速線。主要環境轉換為密閉騎樓 → 開闊屋頂，再下降夜市與河岸。地形高差、門洞和濕線都改變駕駛決策。

## Moving Obstacles

第三段捷運以燈號與聲音預告，橫越獎勵內線；安全主路不關閉。這是新行為提案，目前的列車是在左車道往返，尚未實作支路橫越。週期、煞車距離與通行時間需以共享遊戲時間驗證，不能只做動畫。

## Shortcut

第二段騎樓內街切掉外街彎，但入口、兩次轉向與窄路要成功連接；同一 CP 區間合流。目標是熟練操作能省時間，失誤回主路；實測比較同一車速與起點的耗時，收益數值待測。

## Risk/Reward Route

第七段濕磚內線縮短弧長並有出口加速帶；較早入彎、較低抓地是代價，乾外線提供安全選擇。不能以突然失控或無預告掉落當難度。

## Spectacle Moment

屋頂跳台跨越街谷，捷運在下方通過，玻璃高塔與夜市燈海展開；落點先於演出被看見，鏡頭始終保留車身與落點。演出不自動取代成功操作的回報。

## 驗收方式

- 先證明直行不能刷最高級漂移、左右漂移一致、回正與 Turbo 收尾連續；保留正常撞擊損失，不補回所有速度。
- 灰盒對照普通過彎／成功漂移／安全線／捷徑的時間與操作失誤；不以多放道具盒或單純加速當改進證據。
- 實際鍵盤與觸控試跑，記錄「看不懂」「只能按油門」「撞牆失控」「回報不明顯」的位置；玩家願意立即重跑才是主觀品質驗收的一部分，自動測試不能代替它。
- 實作後依 AGENTS 執行 check、build、實際瀏覽器，涵蓋兩種物理模式、坡道、CP、捷徑、CPU、道具及重生。評閱階段只有檢視／提案；核准後的實作與驗證另記。
