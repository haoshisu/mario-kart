# Web 3D 多人卡丁車遊戲｜分階段技術規格與驗收計畫

> 文件版本：1.2｜更新日期：2026-09-29
> 技術基礎：Next.js（App Router）、React、TypeScript、React Three Fiber、Drei、Rapier、Node.js、Colyseus  
> 產品方向：原創、卡通化 Arcade Kart Racing；電腦／電視作為主要遊戲畫面，玩家掃描 QR Code，以手機作為控制器。  
> 進度來源：Phase 1、2 已於 2026-09-26 完成；Phase 3 於 2026-09-27 完成；使用者於 2026-09-28 確認 Phase 4 真實手機驗收通過，於 2026-09-29 確認 Phase 5 人工驗證完成。Phase 1～5 已完成，Phase 6 本機實作與回歸已推進，正式部署／真機 RC 未完成。

## 0. 產品範圍與共同技術原則

### 0.1 最終產品

- 網頁直接開啟的完整 3D 卡丁車遊戲，使用原創角色、車輛、賽道、音效與圖像素材。
- Host 在電腦上建立房間；其他玩家使用手機掃描 QR Code 加入，手機僅需開啟瀏覽器。
- 支援 **2–4 人**同場，主畫面採用可追蹤所有玩家的共用攝影機；分割畫面為後續擴充項目。
- Arcade 駕駛手感：加速、煞車、轉向、漂移、Mini Turbo、碰撞反彈與 Spin Out；不做擬真汽車物理。
- 完整比賽循環：大廳 → 準備 → 倒數 → 比賽 → 排名 → 結算 → 再來一場。
- 第一個可供朋友玩的多人 MVP 以 Phase 4 為里程碑；道具與正式美術分別在 Phase 5、6 完成。
- 2026-09-28 核准額外單人對戰：1 位真人＋3 位基礎電腦對手，鍵盤／手機兩種建房模式，共用現有賽事與道具；不擴充為複雜 AI 或 Phase 6。

### 0.2 技術與部署決策

| 層級      | 技術                                           | 職責                                                |
| --------- | ---------------------------------------------- | --------------------------------------------------- |
| 網站與 UI | Next.js App Router + React + TypeScript + CSS  | 首頁、Host 遊戲頁、大廳、手機控制器、HUD            |
| 3D 渲染   | React Three Fiber、Three.js、Drei              | 車輛、賽道、第三人稱攝影機、粒子與場景              |
| 物理      | Rapier 3D                                      | 碰撞體、感測區、基礎運動及碰撞偵測                  |
| 遊戲核心  | Framework-independent TypeScript               | 固定時間步長、玩家輸入、Arcade 駕駛、漂移、賽事規則 |
| 即時連線  | Node.js + Colyseus + WebSocket                 | 房間、玩家、輸入轉送、權威遊戲狀態與同步            |
| 3D 資產   | Blender → GLB / glTF                           | 原創卡丁車、角色、賽道與動畫                        |
| 測試      | Vitest、Playwright、伺服器整合測試             | 遊戲邏輯、頁面流程、多玩家與回歸測試                |
| 部署      | Next.js 靜態／應用主機 + 獨立常駐 Node.js 主機 | 網站與需要長連線的遊戲伺服器分開部署                |

**重要邊界**：`app/` 只放頁面與介面；目前 3D 渲染放 `game/components/`；不依賴 React 的模擬與規則放 `game/core/`；Rapier 整合放 `game/physics/`；輸入裝置放 `game/input/`；多人通訊放 `game/network/`。不要將所有遊戲邏輯塞進 `Game.tsx`。

**多人架構遷移**：Phase 1–2 先用本機遊戲模擬；Phase 3 由 Colyseus 建立房間並轉送單人手機輸入，Host 暫時持有模擬狀態；Phase 4 將模擬移至權威遊戲伺服器，以同一套純 TypeScript 遊戲核心降低重寫成本。

### 0.4 建議目錄（可依既有專案調整，不必為了改目錄重寫程式）

```text
src/
├── app/
│   ├── page.tsx
│   ├── game/page.tsx                  # Host 遊戲畫面
│   ├── room/[roomId]/page.tsx         # 房間大廳
│   └── controller/[roomId]/page.tsx   # 手機控制器
├── game/
│   ├── core/                         # 無 React 相依的遊戲邏輯
│   │   ├── kart/
│   │   ├── collision/
│   │   ├── race/
│   │   └── items/
│   ├── rendering/                    # R3F 元件、鏡頭、特效
│   ├── input/                        # Keyboard / Touch / Tilt adapters
│   ├── network/                      # Socket client、狀態插值
│   ├── assets/                       # 模型與資產宣告
│   └── Game.tsx                      # 場景組裝，避免塞入業務規則
└── components/                       # 共用網站 UI
server/
├── rooms/RaceRoom.ts
├── state/
├── systems/
└── index.ts
```

後續如採 monorepo，可將共用遊戲核心、輸入型別及網路訊息協定抽至 `packages/shared/`；不應讓 Node.js 伺服器直接依賴瀏覽器專用模組。

## 6. 自動與手動測試

**自動測試**

- [x] E2E：首頁 → 建房 → 四位控制器加入 → Ready → 比賽 → 結算 → 重賽；物理長路徑可以使用測試模式加速驅動。

## 核准調整：每人獨立遊玩畫面（2026-09-30）

使用者核准從「共看 Host 螢幕、手機遙控」改為各裝置自行顯示 3D 遊戲與操作。新多人房預設房主參賽並計入四人上限，朋友透過連結／QR Code 加入；保留原觀賽房主選項。每位玩家依自己的連線 ID 跟車，手機預設省電畫質並疊加觸控按鈕，電腦可切換鍵盤。權威伺服器、道具與賽事規則沿用。

已通過：lint、TypeScript、120 項規則／連線測試、production build，以及新增的兩個瀏覽器情境（獨立視角、鍵盤／觸控、橫直向、重連、手機房主）。手機直向鏡頭已修正，避免車身被窄畫面裁切。2／3／4 人完整三圈、道具及同房重賽皆已通過；單人鍵盤／手機對戰三位 CPU 亦完成三圈與道具驗證。長賽程測試透過 `?e2e=1` 的唯讀快照事件觀察 20 Hz 權威資料，再以各瀏覽器的鍵盤／觸控事件駕駛，避免讀取節流 HUD 與跨頁自動化造成轉向延遲；仍由伺服器判定完整三圈與成績。長賽程中的多個 Canvas 縮小以控制共用測試 GPU 負荷，完整橫直向畫面另有獨立測試。本機雙人視覺輸入反應量測 280 ms，非真機跨網路數據。

這次變更尚無真實 iPhone／Android 3D 效能驗收；原先手機只作控制器的人工驗收不能沿用為此項驗收，也不表示正式部署已完成。

本次最終瀏覽器回歸共 14 個情境通過（controller 10、solo 2、independent-players 2）；重連情境修正後連續兩次通過，涵蓋重連後 Ready 往返、再次斷網及逾時釋放。`npm run check` 120 項全數通過，production build、最終 lint／TypeScript／diff 檢查通過。真機與公開部署限制如上。
